# 아이템 도감·수집 업적 1.0.0

Paper 26.3 / Java 25용 별도 플러그인입니다. **기본 아이템 1개를 소비해 UUID별 영구 등록**하고, 희귀도와 수집 업적에 따라 작은 보너스를 받습니다. 기존 경제·직업·강화·집·땅·돈 데이터는 그대로 사용합니다.

## 구성과 보상

- **도감 80종**: 숲·농장·광물·바다·제작·네더·엔드·전리품, 분야마다 10종.
- **업적 12개**: 10/30/50/80종 수집과 각 분야 10종 완성. 자동 달성·영구 저장·채팅 안내·효과음·업적 화면을 제공합니다.
- **희귀도**: 같은 분야 안에서 일반 1배, 고급 2배, 희귀 4배, 전설 8배의 아이템 등록 보너스. 각 아이템의 실제 증가량을 등록 전에 표시합니다.
- 분야별 상한의 약 80%는 아이템 등록, 나머지는 분야 완성·전체 수집 업적으로 얻습니다.
- 네더의 별·겉날개·네더라이트 주괴·무거운 코어 등은 전설입니다. 모든 이용자가 완성할 수 있도록 드래곤 알은 필수 항목에 넣지 않았습니다.

| 능력치 | 80종·12업적 전체 완성 상한 | 주요 분야 |
| --- | --- | --- |
| 이동 속도 | +3% | 숲과 채집 |
| 채굴 속도 | +6% | 광물과 채굴 |
| 최대 체력 | +2 HP = 하트 1칸 | 농장과 식량 |
| 공격력 | +0.5 | 네더 탐사 |
| 방어력 | +1 | 제작과 생활 |
| 공격 속도 | +2% | 엔드 탐험 |
| 넉백 저항 | +2%p | 탐험과 전리품 |
| 행운 | +0.5 | 낚시와 바다 |

이동 속도는 지상 걷기·달리기에 적용합니다. 채굴 시간은 도구·블록·기존 마법·틱 단위에도 영향을 받습니다. 행운은 바닐라 낚시 전리품 등 해당 속성을 참조하는 판정에 사용합니다. 체력은 최대치만 늘리며 즉시 회복시키지 않습니다. 효과를 껐다 켜거나 재접속해도 자동 회복·보너스 중첩을 하지 않습니다.

위 상한은 **이 플러그인이 주는 추가량**입니다. 기존 물약과 장비의 효과는 유지합니다. 이동·채굴·공격 속도는 해당 기본 속성에 작은 비율을 더하고, 체력·공격력·방어력·넉백 저항·행운은 작은 고정값을 더합니다. 넉백 저항은 0~1 속성에서 0.02를 더하므로 표에는 2%p로 표시합니다.

## 설치

1. 기존 `ServerStop.cmd`로 서버와 백업 관리자를 종료합니다. 별도 관리자가 없으면 콘솔 `stop` 후 완전히 종료될 때까지 기다립니다.
2. 기존 전체 서버 백업을 만든 뒤 **`KoreanCodex-1.0.0.jar` 한 개**를 서버의 `plugins` 폴더에 넣습니다. 같은 KoreanCodex JAR가 있으면 이전 파일을 서버 폴더 밖에 보관하고 새 JAR 한 개만 남깁니다.
3. 기존 `ServerStart.cmd`로 시작합니다. `/도감`, `/업적`, `/도감효과`를 확인하세요.

추가 모드·리소스팩·Vault가 필요하지 않습니다. 기존 KoreanMenu가 있으면 비어 있는 20·26번 칸에 도감·업적 버튼을 연결합니다. 다른 버튼이 있으면 덮어쓰지 않으며 `plugins/KoreanCodex/config.yml`의 `메뉴-연결: false`로 연결을 끌 수 있습니다.

이 JAR와 관련 파일을 사용자 Windows에 원격 설치한 상태는 아닙니다. 실제 게임 접속 검증과 MockBukkit 검증을 구분해 기록합니다.

## 사용법

| 명령어 | 기능 |
| --- | --- |
| `/도감`, `/아이템도감` | 분야별 등록 현황과 목록 |
| `/도감 등록` | 손에 든 아이템에 해당하는 등록 확인 화면 |
| `/업적` | 12개 목표·달성 상태·추가 보상 |
| `/도감효과` | 현재 능력치 보너스와 전체 상한 |
| `/도감효과 켜기`, `/도감효과 끄기` | 내 효과만 켜거나 끄기, 등록 기록 유지 |

도감의 아이템을 클릭하면 **소비 확인창**이 나옵니다. 확인해야 가방의 동일한 기본 아이템 1개를 소비합니다. 같은 아이템은 한 번만 등록하며 재료 부족·등록 취소·이미 등록한 항목은 소비하지 않습니다.

이름·설명·마법·손상·커스텀 모델·추가 데이터가 없는 기본 아이템만 사용합니다. 예를 들어 겉날개는 이름·마법·손상이 없는 상태로 준비하세요. 장비칸과 보조 손은 등록 재료로 쓰지 않습니다. 등록은 생존·모험 모드에서 가능하며 효과도 이 두 모드에 적용합니다. 메뉴에서 아이템을 가져가거나 숫자키로 바꾸는 동작은 차단합니다.

`아이템별보너스.md`에 80종의 희귀도와 실제 증가량을 제공합니다. 물건을 등록해 생긴 효과는 아이템을 보유하지 않아도 유지합니다. 등록은 되돌리는 기능을 제공하지 않으므로 귀한 아이템은 확인창을 읽고 선택하세요.

## 저장·백업·중단 복구

자료는 `plugins/KoreanCodex/도감.db`에 저장합니다. 등록·업적·개인 효과 설정·등록 거래를 SQLite로 관리합니다. 효과는 별도의 임시 속성 수정자로 적용하고 재접속 시 기록에서 다시 계산합니다. 기존 기본 속성·물약·다른 플러그인 수정자를 지우지 않습니다. 정상 종료·접속 종료 시 자체 효과를 제거합니다.

기존 Windows 관리자의 **전체 서버 백업**에 이 폴더도 포함해 보관하세요. KoreanEconomy의 `/서버백업`은 해당 경제 DB용이므로 별도 도감 DB까지 보관하는 전체 백업과 구분합니다. `/도감관리 백업`은 도감 DB만 일관된 스냅샷으로 복사합니다. 저장 중인 DB만 파일 탐색기로 복사하는 대신 정상 종료 후 전체 폴더 또는 DB 스냅샷을 사용하세요.

아이템과 SQLite 사이를 하나의 원자적 거래로 보장하지는 못합니다. 서버가 도중에 꺼지거나 플레이어 저장이 실패한 등록은 확인 대기로 잠그며 자동 재소비·환불·확정을 하지 않습니다. 등록 전/후 가방의 해시·슬롯·소비 전 수량과 플레이어 저장 표식을 남깁니다. 등록 기록을 임의 삭제하면 재등록이 가능해지므로 복원은 같은 시점의 월드·플레이어·플러그인 자료를 함께 사용하세요.

운영자 전용 명령:

```text
/도감관리 거래
/도감관리 번호 거래번호
/도감관리 조회 닉네임
/도감관리 완료 거래번호 확인
/도감관리 취소 거래번호 확인
/도감관리 백업
```

`완료`는 실제 1개가 소비된 것을 확인한 뒤 등록만 확정합니다. `취소`는 실제 소비가 없거나 운영자가 이미 아이템을 복원한 것을 확인한 뒤 잠금만 정리합니다. 둘 다 가방을 자동 수정하거나 희귀 아이템을 지급하지 않습니다. 확인 대상 플레이어의 영구 데이터 표식 키는 `koreancodex:pending_registration`이며 번호와 BEFORE/CONSUMED 단계를 참고할 수 있습니다. 기록·표식은 확인 자료이며 사용자가 별도로 플레이어 파일만 롤백한 상황까지 자동 판별하지 않습니다.

## 권한·구현·검증

- 일반 기능 `koreancodex.use`: 기본 허용. 관리 기능 `koreancodex.admin`: 기본 OP.
- `효과-사용: false`로 전체 보너스를 중지할 수 있습니다. 설정 파일을 바꾼 뒤 서버를 완전히 재시작하세요.
- 실제 Paper 26.3 `df120fd` API로 컴파일합니다. SQLite JDBC 3.51.0.0의 원본 드라이버·플랫폼별 네이티브 파일·라이선스를 JAR에 포함합니다. 서버의 SLF4J를 사용합니다.
- `python3 korean-codex/test.py`는 실제 MockBukkit 26.3·Paper API·SQLite로 등록·업적·보너스·메뉴·장애 시나리오를 검사합니다. MockBukkit이 구현하지 않은 `Player.saveData()`는 호출 횟수와 실패 주입으로 대체하므로 실제 NBT 파일 쓰기나 전원 차단 성공으로 보고하지 않습니다. MockBukkit 기본 맵에 없는 채굴 속도는 바닐라 기본값 1을 넣은 실제 MockBukkit 속성 인스턴스로 준비합니다.
- `python3 korean-codex/build.py`가 JAR·명세표·검증 결과·설치 묶음을 만듭니다. 기존 `/workspace/toolchains`의 Java 25·Paper API와 `survival-pack/vendor/tycoon/sqlite-jdbc.jar`를 사용합니다.
- 실제 Windows 설치·Minecraft 클라이언트 접속·네이티브 전투/채굴 시간·NBT 복구는 이 환경에서 미검증입니다. `validation.json`에 범위를 기록합니다.
