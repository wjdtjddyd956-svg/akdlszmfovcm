# 시티 이코노미 1.0 · Minecraft Java 26.3

현실적인 도시·경제풍으로 만든 리소스팩입니다. 차콜·틸·아이보리와 금색을 기본으로, 편의점·은행·부동산·식당·현장 작업 장비를 표현했습니다.

`catalog.json`이 이름·아이템 모델 ID·원본 시트 위치·블록 대응표의 기준입니다. 아이콘은 네이티브 `minecraft:item_model`을 사용합니다. OptiFine·ItemsAdder·Oraxen·커스텀 폰트를 추가할 필요가 없습니다. 다른 서버의 비공개 이미지나 브랜드 로고를 복사하지 않았으며 원본 생성 이미지도 `art/`에 보관합니다.

## 1. 클라이언트에 팩 넣기

1. **한 가지 방식**을 선택하세요.
   - 메뉴·요리만: `CityEconomy-26.3-1.0.0.zip`
   - 메뉴·요리와 도시 건축을 함께: `CityEconomy-Complete-26.3-1.0.0.zip`
   - 건축 재질만: `CityBuild-26.3-1.0.0.zip` (기본 팩과 함께 선택해도 됩니다.)
2. Minecraft에서 **설정 → 리소스팩 → 팩 폴더 열기**로 이동합니다. 기본 Windows 경로는 `%appdata%\.minecraft\resourcepacks`입니다.
3. 선택한 **ZIP을 풀지 않고** 넣고 게임에서 활성화합니다. 예전 `생활타이쿤-리소스팩-26.3.zip`을 사용 중이면 새 팩이 더 높은 우선순위가 되도록 하거나 예전 팩을 선택 해제하세요.

각 이용자 클라이언트가 팩을 선택해야 해당 화면에서 보입니다. 서버의 `plugins` 폴더는 리소스팩 ZIP을 넣는 곳이 아닙니다.

## 2. 기존 한글 메뉴에 연결

1. 현재 1.2 서버는 `ServerStop.cmd`로 서버와 백업 관리자를 함께 종료합니다. 별도 관리자가 없으면 콘솔 `stop` 후 종료를 기다리세요.
2. 서버 `plugins` 폴더에 **`CityTextures-1.0.0.jar` 한 개**를 넣습니다. 같은 CityTextures의 이전 JAR가 있으면 별도 폴더에 보관하고 새 JAR 한 개만 남기세요. 기존 KoreanMenu·KoreanEconomy·Vault·Essentials·땅·임무·백업 파일은 계속 사용합니다.
3. 기존 `ServerStart.cmd`로 시작합니다. 팩을 적용한 이용자는 `/도시팩 켜기`를 입력하고 쉬프트+F 또는 `/메뉴`를 여세요.
4. `/도시팩 미리보기`에서 32종을 확인합니다. 미리보기 창의 아이템을 가방으로 가져갈 수 없습니다. `/도시팩 끄기`는 내 메뉴 아이콘을 기본 모습으로 복원합니다.

기본값은 자동 다운로드 요청 꺼짐, 메뉴 아이콘도 이용자가 직접 켜기입니다. 수동 선택은 기본적으로 다음 접속에도 기억합니다. 클라이언트에서 팩을 삭제했으면 `/도시팩 끄기`도 사용하세요. 이 명령은 메뉴 설정이며 클라이언트에서 선택한 리소스팩 자체를 제거하지 않습니다.

보조 플러그인은 기존 **KoreanMenu**, **KoreanEconomy 1.2의 생활 메뉴**, **KoreanEconomy 2.0/2.0.1의 메뉴·상점**을 인식합니다. 실제 소유 플러그인을 확인한 메뉴의 표시용 아이템만 바꿉니다. 지갑이나 개인 가방·바닥 아이템·장비·돈·임무 데이터는 처리하지 않습니다. 플러그인을 끄거나 메뉴를 닫으면 바꿨던 메뉴 모델 값을 원래 값으로 복원합니다.

## 3. 실제 요리 아이템에도 적용

현재 서버에 1.2만 설치했다면 기존 메뉴 아이콘부터 사용할 수 있습니다. 요리 10종은 앞서 제공한 **KoreanEconomy 2.0 이상**의 요리 기능과 연결됩니다.

모든 이용자가 팩을 적용한 후 `plugins/KoreanEconomy/config.yml`에서 아래 항목을 변경하고 서버를 다시 시작하세요.

```yaml
리소스팩-사용: true
```

이후 새로 만든 요리에 도시 식당 아이콘이 붙습니다. 기존 2.0 요리의 `tycoon:mill_bread` 같은 모델 ID를 그대로 사용하므로 이미 전용 모델이 붙은 요리도 새 모습으로 표시됩니다. 일반 기본 음식의 외형은 별도 메뉴 연결 없이 일괄 교체하지 않습니다. 음식 재료·판매 가격·영양·섭취 효과·게임 밸런스는 기존 플러그인과 기본 아이템의 값을 사용합니다. 이전에 모델 없이 만든 음식은 기존 모습으로 남으며 기존 매입 규칙을 계속 사용합니다.

## 4. 건축팩으로 달라지는 블록

선택한 이용자의 모든 월드에서 아래 **기존 블록의 표면**이 바뀝니다. 실제 블록 종류·월드 파일·설치한 구조물은 유지됩니다.

| 기본 블록 | 보이는 재질 |
| --- | --- |
| 검은색 콘크리트 | 아스팔트 도로 |
| 회색 콘크리트 | 노출 콘크리트 |
| 회백색 콘크리트 | 도시 보도 블록 |
| 하얀색 콘크리트 | 아이보리 외벽 |
| 벽돌 | 도심 적벽돌 |
| 윤나는 안산암 | 화강석 바닥 |
| 매끄러운 돌 | 대형 석재 포장 |
| 철 블록 | 철제 설비 패널 |

128×128 건축 텍스처는 각 재질이 반복됐을 때의 모양도 `건축재질-반복확인.png`에 제공합니다. 조명·셰이더·거리 설정에 따른 실제 3D 화면은 클라이언트에서 확인해야 합니다.

## 5. 서버에서 선택 다운로드 요청하기

`plugins/CityTextures/config.yml`에는 기본 아이콘 팩의 HTTPS ZIP 주소와 해당 ZIP의 **SHA-1 40자리**가 들어 있습니다. 기본은 `자동요청: false`입니다. 공개 다운로드가 가능한 호스트를 확인한 뒤 true로 바꾸고 `/도시팩 새로고침` 또는 재시작하면 다음 접속부터 요청합니다. 현재 접속자는 `/도시팩 받기`를 사용할 수 있습니다.

```yaml
자동요청: true
팩-주소: 공개된_ZIP의_HTTPS_직접주소
체크섬-SHA1: 그_ZIP의_SHA1_40자리
```

GitHub 저장소가 비공개이거나 다운로드에 로그인이 필요하면 Minecraft 클라이언트는 해당 주소에서 받을 수 없습니다. 공개 HTTPS 호스팅을 사용하거나 수동으로 ZIP을 배포하세요. 변경한 ZIP은 새 SHA-1로 함께 갱신합니다. 전체 팩을 자동 배포하려면 주소를 Complete ZIP으로 바꾸고 `SHA1.txt`에 있는 **Complete의 해시**를 사용하세요.

다른 서버 팩을 지우지 않고 이 팩의 고유 ID로 추가 요청합니다. 강제 적용·거절 시 추방은 설정하지 않습니다. 이 팩의 적용 성공 상태를 받은 뒤 메뉴 아이콘을 켜고, 다운로드 실패·거절 시 기본 메뉴 아이콘으로 복귀합니다. 수동으로 선택한 로컬 팩의 실제 적용 여부를 서버가 감지하는 기능은 아니므로 수동 방식에서는 `/도시팩 켜기`를 사용합니다.

운영자 `/도시팩 관리`는 설정 형식과 상태를 표시하며 외부 호스트 접근 성공까지 검사하지는 않습니다. 일반 이용자는 다른 사람의 설정을 바꿀 수 없습니다.

## 개발·검증

```bash
python3 city-resourcepack/tools/build.py
python3 city-textures/test.py
python3 city-resourcepack/tools/test_preview.py
python3 city-resourcepack/tools/validate.py
python3 city-resourcepack/tools/package.py
```

빌드는 Python Pillow·Noto CJK 폰트·Java 25 컴파일러와 앞서 준비한 실제 Paper 26.3 API를 사용합니다. 원본 아틀라스에서 셀을 추출하고 여백·게임 해상도를 맞추며 원본 PNG는 덮어쓰지 않습니다. 셀 경계에서 넘어온 이웃 그림 조각과 블록 경계의 아틀라스 번짐은 추출 범위로 제외합니다. Java 실행 환경·API 경로는 기존 `TYCOON_TOOLCHAINS`, `TYCOON_JDK`, `PAPER_API_JAR` 설정을 사용할 수 있습니다.

모델 JSON 참조·PNG 크기/투명도·ZIP 구조·SHA-1과 보조 플러그인을 검사합니다. 실제 KoreanMenu를 연 MockBukkit 검사와 브라우저 미리보기 검사를 구분해 기록합니다. **Minecraft 26.3 클라이언트 렌더링과 사용자 Windows 서버의 실제 설치는 이 환경에서 확인하지 않았습니다.** 상세 결과는 배포 폴더 `validation.json`을 참고하세요.
