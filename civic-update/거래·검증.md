# 거래 처리와 검증 범위

## 거래 저장 방식

기존 Vault 지갑을 그대로 사용하며 별도 화폐는 만들지 않습니다. `생활경제.db`의 기존 거래 엔진에 먼저 영수증을 예약하고, 돈 처리 → 가방 저장 → DB 확정을 순서대로 실행합니다. SQLite 내부의 필지 소유권·물품 상태·판매 적립금·영수증은 하나의 DB 거래로 확정합니다. Vault와 플레이어 NBT가 SQLite와 원자적으로 저장된다고 가정하지 않습니다.

- 마을 설립·확장은 돈 처리 전에 청크를 예약·보호합니다. 처리 도중에는 일반 플레이어의 건축·상자 접근을 막습니다.
- 필지 구매를 예약하면 원래 소유권을 지우지 않고 보호 상태를 잠급니다. 지갑이 거절하면 기존 소유자·판매가·보호를 복구합니다. 완료하면 새 소유자와 판매 적립금을 함께 기록합니다.
- 물품은 실제 `ItemStack.serializeAsBytes()` 데이터로 보관합니다. GUI용 복사본에 설명을 붙여도 보관 원본·실제 구매 물품은 바꾸지 않습니다.
- 물품 판매 예약은 가방 저장이 끝나야 공개합니다. 구매·회수는 먼저 가방 공간을 계산합니다. 오래된 손 아이템·가격·상태와 중복 클릭은 거절합니다.
- 판매대금은 판매자 접속 여부와 관계없이 DB에 쌓습니다. 수령할 때 예약한 적립금만 차감하므로 그사이 발생한 판매대금은 남습니다.
- 돈 처리 결과 불명, 가방 복구 실패, 최종 저장 실패 또는 처리 중 재시작은 `REVIEW`로 남깁니다. 돈·아이템을 자동 재지급하지 않습니다. 같은 이용자의 경제·농사·마을 미결 거래도 공유 잠금으로 확인합니다.
- Core 스키마 2의 `land_tags`는 마을 필지를 기존 개인 땅의 개수·첫 땅 무료 혜택에서 제외하고 `/땅보호 포기`에 의한 해제를 막습니다.

## 운영자 거래 정리

1. `/마을거래 대기`에서 번호를 찾고 `/마을거래 번호 번호`로 내용·상태·금액을 확인합니다.
2. 서버를 보존하고 실제 Vault 잔액, 가방·플레이어 데이터, 보관 물품, 판매대금, 필지 소유권, 로그와 백업을 대조합니다. 구매/회수가 실제 지급됐다면 물품을 다시 보내지 마세요.
3. **돈과 아이템의 실제 결과를 먼저 수동으로 맞춥니다.** 완료된 거래로 맞췄으면 `/마을거래 완료 번호 확인`, 원상 복구한 거래면 `/마을거래 취소 번호 확인`을 실행합니다. 이것은 DB 상태를 확정하는 명령이며 돈·아이템을 자동 지급·회수하지 않습니다.
4. 기존 `/경제기록`의 일반 정리로 마을 거래를 넘기지 않습니다. 농사 미결 거래는 기존 농사 운영 명령을 사용합니다. 저장소 오류로 모듈이 중지됐다면 정리 후 서버를 완전히 재시작합니다.

`CIVIC_TOWN`=설립, `CIVIC_EXPAND`=확장, `CIVIC_PLOT_BUY`=필지 구매, `CIVIC_ITEM_LIST`=물품 등록, `CIVIC_ITEM_BUY`=물품 구매, `CIVIC_ITEM_RETURN`=회수, `CIVIC_COLLECT`=판매대금 수령입니다. 영수증에는 개발·운영 식별자가 그대로 기록되며 일반 이용자 화면은 한글입니다.

## 실행한 검사

최종 수치·해시는 배포 폴더의 `validation.json`, `installer-validation.json`, `packaged-sqlite.json`, `SHA256SUMS.txt`를 기준으로 합니다.

- 공식 Paper 소스 df120fd에서 만든 실제 26.3 API로 컴파일, Java 21 바이트코드 / 실행 API는 Java 25 이상. 테스트용 Bukkit API를 제작하거나 배포 JAR에 넣지 않습니다.
- 실제 MockBukkit 26.3:4.120.0에서 마을·인접 확장·가격 변경·재판매·권한 이전·상자 접근 회수·판매 보관·정확한 커스텀 물품 직렬화·가방 부족·중복 클릭·판매자 오프라인·수령 중 신규 적립을 검증합니다.
- 지갑 거절/예외·가방 저장 실패·최종 DB 실패를 주입하고 환불·잠금·수동 정리·자동 재지급 방지를 확인합니다. 플레이어 NBT의 실제 디스크 저장은 MockBukkit 대신 저장 호출·실패를 주입해 검증합니다.
- 실제 SQLite로 스키마 1→2 업그레이드, 기존 개인 땅·친구·직업·다른 확장 테이블 유지, 예약 후 재시작, 거절 후 재시작, 미결 거래 수동 정리를 검증합니다. 배포 JAR의 SQLite 네이티브 라이브러리로도 별도 재시작 검사를 수행합니다.
- 기존 경제·농장·도감·도시팩의 회귀 검사를 실행합니다. 기존 테스트의 MockBukkit 미구현 부분은 기존과 동일하게 플레이어 저장·일부 속성/엔티티 표시 기본값만 대체합니다.
- 실제 배포 JAR와 임시 서버 파일 트리로 설치기 해시·버전·실행 잠금·중복 교체·전체 백업·복원·기존 DB/잔액/월드 바이트 보존을 검사합니다. Windows PowerShell 실행 자체를 Linux에서 검증했다고 주장하지 않습니다.
- 미리보기는 실제 플러그인 인벤토리의 슬롯·한글 설명을 MockBukkit에서 추출해 실제 팩 PNG로 그린 자료입니다. 실제 게임 스크린샷이 아닙니다.

GriefPrevention 16.18.8 공개 소스의 `ClaimCreatedEvent`, `ClaimResizeEvent`, `getClaims()` 계약에 맞춘 선택 연동입니다. 기존 GP 영역은 전체 경계를 검사하며 새 GP 생성·확장이 마을 필지를 포함해 둘러싸는 경우도 차단합니다. API 확인 실패 시 신규 마을 필지를 거절하고 보호 도구 처리를 보수적으로 막습니다. **이번 버전의 실제 GP·WorldGuard 서버 이벤트 조합은 미검증**이며 기존 서버 복제본에서 먼저 확인해야 합니다. WorldGuard 관리 영역·전역 관리 영역과 마을 필지의 겹침은 허용하지 않습니다.

이번 버전의 Windows 운영 적용, 실제 클라이언트 리소스팩 다운로드/렌더링, 실제 플레이어 NBT 충돌 복구, 10인 장시간 부하 검사는 수행하지 않았습니다. 이전 배포에서 수행한 Windows 실게임 검증을 새 기능의 검증으로 재사용하지 않습니다.
