# 검증 결과

## 운영 서버

- Windows PowerShell로 설치 전 백업을 만든 뒤 기존 월드·플러그인 데이터에 1.2.0을 적용했습니다. Paper 26.3 build 238이 10인 설정으로 시작했으며, EssentialsX 본체와 스폰은 공식 개발 빌드 1833입니다. Vault, QuickShop, GriefPrevention의 WorldGuard 연결과 Prism의 SQLite 기동을 확인했습니다.
- 스폰 근처에 잡화상인과 임무안내 NPC를 배치했습니다. 정상 저장으로 생성한 백업의 월드 엔티티 데이터에 두 NPC의 타입, 좌표, 상점·임무 구분이 들어 있는 것을 확인했습니다.
- Windows 백업 관리자에서 즉시 백업을 요청해 정상 저장·종료, 별도 프로세스 ZIP 생성, 재기동, 성공 로그를 확인했습니다. ZIP의 SHA-256과 월드·경제 설정·땅 설정·Prism DB 항목을 확인했습니다.

## 별도 Paper 26.3 서버 복사본

다음은 실제 Paper API와 Vault·EssentialsX·GriefPrevention·Prism을 로드한 서버의 결과입니다. 자동화 클라이언트 두 개는 테스트 환경에서만 ViaBackwards로 접속했습니다. 테스트용 어댑터와 도구는 설치 ZIP과 운영 서버에 포함되지 않습니다.

- 신규 UUID 시작 잔액 1,000원, 두 일반 계정 간 1원 송금, 일반 계정의 돈 지급 및 운영 명령 차단, 한글 메뉴·집 저장·집 이동·스폰 이동을 확인했습니다.
- 임무 NPC를 우클릭해 수락하고 밀 16개를 납품했습니다. 실제 가방에서 밀이 빠지고 48원이 한 번만 지급됐습니다. 기존 일일 접속 보상도 연속 실행에서 한 번만 지급됐습니다.
- 다이아몬드 하루 매입 12개, 초과 요청 거절, 잔액 부족 구매의 무변경을 확인했습니다. 서버 재기동 후 납품 수령 상태와 매입 한도가 유지됐습니다.
- 다 자란 밀 수확의 농부 보상, 자연 광석 채굴의 광부 적립·수령, 중복 수령 차단을 확인했습니다. 설치 광석은 테스트 도구가 실제 Bukkit 설치 이벤트를 호출해 표시했고, 연결된 계정이 캤을 때 광부 보상에서 제외됐습니다.
- 테스트 도구가 실제 GriefPrevention API로 지정한 땅에서 일반 계정의 건축·상자 접근 권한과 타인 땅 해제를 확인했습니다. 한글 상자초대·회수 명령이 상자 권한을 바꾸는 것도 확인했습니다. 금 삽 두 점 지정은 이 자동화 검사에 포함되지 않았습니다.
- Prism에서 블록 설치·파괴와 상자 삽입·제거 기록을 조회했습니다. 블록 미리보기를 적용해 광석 블록을 복구했고, 상자에서 꺼낸 다이아몬드도 복구했습니다. 상자 테스트는 실제 접속 계정의 인벤토리 클릭을 사용했으며 상자 열기는 테스트 도구가 수행했습니다.
- Windows 복원 스크립트로 서버를 종료한 복사본을 복원해 임시 변경이 제거되고 서버가 다시 시작되는 것을 확인했습니다.

## 별도 검사와 남은 검증

- JDK 27에서 Java 25 대상으로 실제 Paper 26.3 build 238, Vault, GriefPrevention API를 사용해 컴파일했습니다.
- 장부 단위 검사 11개에서 재기동 후 미결 거래 잠금, 실패 취소, 성공 확정, 중복 예약 차단과 날짜 경계를 확인했습니다. 실제 자정 경과와 전원 강제 중단은 이 검사와 별개입니다.
- 자연 낚시를 끝까지 완료하는 테스트, 10인 동시 부하 테스트, 운영 서버에서 12시간이 실제로 경과하는 예약 백업 관찰은 미실시입니다. 백업 요청과 자동 예약은 같은 정상 종료·스냅샷·압축 경로를 사용합니다.
- 운영 명령과 플레이어 메뉴·도움말은 한국어입니다. Prism 조회 상세와 일부 기본 플러그인 메시지는 영어로 표시될 수 있습니다.
