# 농장 Windows 1.0.1 검증

2026-11-11, Windows 11 / 실제 설치된 Paper 26.3 build 238 API·서버 / JDK27. 기존 main `ee8edb8`의 5작물 구현을 재사용했습니다. API 버전 문자열만 바꾸거나 테스트용 Bukkit 인터페이스로 컴파일하지 않았습니다. API SHA-256과 소스별 해시는 `build-info.json`에 기록했습니다. JAR는 기존 검증된 Windows SQLite 배포본을 의존성 운반체로 사용하며 Paper/Vault/WE/WG/MockBukkit 클래스를 동봉하지 않습니다.

실제 Paper 검사: 기존 메뉴의 도감/업적 보존 및 농장 연결, NPC 씨앗 구매와 정확한 Vault 차감, 실제 10초 타이머 성장, 물 부족/빛 부족/청크 언로드 시 중지, 네 단계 ItemDisplay 모델, 작물 경작지 파괴 차단, 가방 부족 시 변경 없음, 재성장 3종/씨앗 반환 2종, 실제 농부 XP·적립금, 다섯 GUI 레시피의 재료 소비·빈 양동이 반환, 기존 요리 NPC 매입, 개인/품목별 매입64개 한도, 정품 도감5종 각1개 소비·체력0.1HP/속도0.1%·즉시 회복 없음, 재시작 유지, 불확실 거래 수동 정리 중복 방지, 타인 수확/WorldGuard 스폰/GP 타인 땅 거절을 검사했습니다.

긴 작물 대기와 요리 해금은 RCON 전용 FarmProbe로 성장/XP를 조정한 테스트 fixture입니다. 심기·수확 일부는 실제 플러그인 메서드를 호출하는 계측이며 마우스로 플레이한 동작과 구분합니다. 실제 타이머의 물/빛/언로드 조건은 시간을 기다려 검사했습니다. 처음 언로드 검사는 다른 접속 테스트 계정이 근처 청크를 로드해 실패했고, 모든 계정을 시야 밖으로 옮긴 뒤 정상 통과했습니다.

SQLite 최종 완료에 오류를 주입하면 플레이어 NBT에 이미 저장된 수확물은 남고 작물과 영수증은 LOCKED/REVIEW가 됩니다. 직업 보상은 아직 지급되지 않습니다. 실제 서버 재시작 후에도 추가 수확이 거절되고, 운영자 완료 처리로 기록과 직업 보상만 한 번 확정하며 아이템을 재지급하지 않는 것을 확인했습니다. 이것은 돈·아이템·DB를 하나의 원자적 시스템이라고 주장하는 방식이 아닙니다.

## 운영 서버 적용

`ServerStop.cmd`로 기존 Paper와 Windows 백업 관리자를 정상 종료했습니다. 전체 냉백업 `전체서버-20261111-144839-428.zip`을 검증·별도 복원하고, 설치기의 추가 전체 백업 `전체서버-20261111-145531-041.zip`을 검증한 뒤 세 JAR를 설치했습니다. 백업·교체 전 JAR는 실제 서버의 `tycoon-server-backups`에 있습니다. 백업 자체와 사용자 데이터는 GitHub/설치 ZIP에 올리지 않았습니다.

경제2.0.1/도감1.0.1만 교체하고 농사1.0.1을 추가했습니다. 기존 월드·잔액·집·땅·NPC·상점·직업·임무·도감 데이터는 유지했습니다. EssentialsX2.22.1-dev+28-f8724e2 본체/Spawn·Vault·GP16.18.8·Prism4.5·WE/WG·백업 관리자를 유지합니다. 테스트용 FarmProbe/CodexProbe/ViaVersion/ViaBackwards를 운영 서버에 넣지 않았습니다.

적용 후 기존 `/백업 지금`으로 Windows 관리자의 월드 포함 냉백업·자동 재시작도 실행했습니다. 15:03 백업 성공, ZIP CRC·SHA-256 사이드카·경제 SQLite 무결성·farm_plots·도감 DB·월드·새 농사 JAR 포함을 확인했습니다(`backup-validation.json`). `/서버백업 지금`의 DB/설정 스냅샷도 별도로 성공했습니다. 현재 운영 서버는 다시 실행 중입니다.

## 실제 26.3 게임 화면

합성 일반 계정으로 실제 Minecraft26.3에 접속해 팩 거절 후 접속 유지, 기본 아이콘 씨앗 구매40원, 쉬프트+F 농장 버튼, 서버 팩 다운로드/SHA1 확인과 적용 성공을 확인했습니다. 같은 씨앗을 **실제 마우스 우클릭**으로 심어1개 소비했고, 네 단계 모델을 직접 보았습니다. 단계 확인은 progress를 0/25/60/100%로 조정한 가속 fixture입니다. 수확 우클릭으로 딸기3개·농부XP2·적립금2원을 받았고 재성장25%로 돌아갔습니다. NPC 우클릭 메뉴에서 딸기1개를 판매해8원(잔액960→968)을 받은 뒤 쉬프트+F → 도감 → 도시 농장 → 딸기 → 확인에서1개 소비·체력20→20.02HP·현재 체력20유지를 확인했습니다. 게임 안 `/농사`나 시작 명령은 입력하지 않았습니다.

**클라이언트 제한:** 이 PC의 테스트 Java25/27 일반 JVM 모드에서 LWJGL/FFM 호출 중 JVM EXCEPTION_ACCESS_VIOLATION이 두 번 발생했습니다(서버 오류나 거절 추방 아님). 원인을 확정하지 않았고 JVM/라이브러리를 배포물로 교체하지 않았습니다. 기존 Java27의 `-Xint` 진단 모드에서는 팩 적용과 위 플레이 흐름을 완료했습니다. 따라서 일반 런처/JVM 프로필에서 안정적으로 팩을 전환하는지 최종 확인이 남아 있습니다. 진단 모드는 느리므로 일반 이용자 기본 설정으로 강제하지 않습니다. 테스트 계정은 localhost/offline 복제본 전용이며 운영 서버의 online-mode와 인증 설정은 유지했습니다.

## 남은 범위

운영 서버에 로그인한 실제 이용자의 종단 플레이, 10명/최대256작물 동시 부하, 강제 전원 차단·파일시스템/디스크 고장, 모든 팩 조합과 GPU 검사는 완료하지 않았습니다. 정상 종료/재시작과 SQLite 오류 주입 검사를 강제 전원 차단 보장으로 확대하지 않습니다.
