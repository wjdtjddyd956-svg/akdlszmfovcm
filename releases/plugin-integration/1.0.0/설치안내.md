# Windows 설치·백업·복원

검증 조합: Paper 26.3 build238, Economy 2.0.2 / Codex 1.2.1 / Menu 2.1.0 / Farming 1.0.2 / CityTextures 1.1.1. EssentialsX·Spawn은 기존 호환 개발 빌드를 유지합니다. 2.22.0을 넣지 않습니다.

1. ZIP을 **서버 폴더 밖**에 풉니다. Install-PluginIntegration.cmd를 실행하고 server.properties가 있는 서버 폴더를 지정합니다.
2. 공식 무료 5개 파일을 내려받아 이름·버전·SHA-256을 검사합니다. 실패하면 서버 파일을 바꾸지 않습니다.
3. 실제 플러그인 식별자로 중복·버전을 확인합니다. 다른 빌드·수정된 설정은 자동 덮어쓰지 않습니다. 원본 백업 후 별도로 병합해야 합니다.
4. 기존 ServerStop.cmd로 서버와 백업 관리자를 정상 종료합니다. 모든 월드 잠금 검사 후 전체 서버 ZIP을 만들고 모든 파일 SHA-256을 검증합니다. 실패 시 설치하지 않습니다.
5. 새 JAR 6개와 한국어 설정을 넣습니다. 기존 16개 JAR·데이터 폴더를 유지합니다. GriefPrevention은 확인한 원본 메시지 해시와 일치할 때만 안내를 교체합니다. 전체 백업과 plugin-integration-config-backup-날짜 폴더에 원본을 보존합니다.
6. 완료 후에도 서버는 종료 상태입니다. 기존 ServerStart.cmd로 시작하고 logs/latest.log에서 새 플러그인 6개 활성화·오류를 확인합니다. /reload는 사용하지 않습니다.
7. 일반 이용자로 쉬프트+F → 마을 정보 → 직업/도감 → 복귀, 기존 NPC 상점·씨앗·요리를 확인합니다. TAB 잔액과 /돈, 도감 수와 /도감, 농부 레벨과 /직업을 대조합니다. 팩 거절·재접속도 확인합니다.

다운로드만 하거나 사전 검사할 수도 있습니다.

    .\Install-PluginIntegration.ps1 -DownloadOnly
    .\Install-PluginIntegration.ps1 -ServerPath '서버 전체 경로' -CheckOnly
    .\Install-PluginIntegration.ps1 -ServerPath '서버 전체 경로'

Java 경로가 다르면 -JavaPath '기존 서버용 Java 25 이상 실행 파일'도 지정합니다.

추가 파일: LuckPerms-Bukkit-5.5.91.jar, Chunky-Paper-1.5.66.jar, PlaceholderAPI-2.12.3.jar, TAB-6.2.1.jar, DecentHolograms-2.10.2.jar, KoreanServerBridge-1.0.0.jar. 기존 JAR 교체 목록은 **없습니다**.

## 월드 경계·지형 생성

기존 리전·집·보호 구역·농장·NPC를 먼저 확인합니다. 건축물이 바깥에 남는 경계를 설정하면 안 됩니다. 기존 운영자의 경계도 임의로 바꾸지 마세요. 네더/엔드·새 야생 월드는 별도 검토합니다.

이번 서버는 기존 오버월드 리전이 x -1024~511, z -512~1535에 들어가는 것을 확인한 뒤 중심 0,0 / 경계 지름 4096 / 최초 생성 반경 512를 적용 대상으로 정했습니다. **경계 전체 생성이라는 뜻은 아닙니다.** 실제 완료 여부는 검증결과를 확인하세요. 다른 서버에 그대로 복사하지 마세요.

현재 월드·경계를 확인한 뒤 서버 콘솔에서 설정합니다. 일반 이용자에게 생성 권한을 주지 않습니다. 부하가 크면 /지형생성 일시정지 후 이용자가 적을 때 계속합니다. 재시작 시 자동 계속은 꺼져 있습니다.

    worldborder center 0 0
    worldborder set 4096
    chunky world world
    chunky center 0 0
    chunky radius 512
    chunky start
    chunky progress

## 자동 백업·전체 복원

기존 Windows 백업 관리자를 유지합니다. 주기·보관 개수·저장 경로는 life-tools/backup.json에서 조정합니다. /백업 지금은 정상 종료 후 월드·플러그인 자료를 보관하고 재시작합니다. 성공/실패: life-control/backup.log, 현재 상태: life-control/status.txt. /서버백업의 경제 DB 스냅샷은 전체 월드 백업이 아닙니다.

설치 직전 전체 백업은 서버 안 tycoon-server-backups/전체서버-날짜.zip입니다. 다음 명령은 모든 파일 SHA-256을 검증합니다.

    & 'Java 실행 파일 전체 경로' -jar .\InterfaceInstaller.jar 검증 '전체 백업 ZIP 경로'

복원은 ServerStop.cmd로 서버와 관리자를 종료한 뒤 수행합니다. 백업을 서버 폴더 밖에 복사해 둡니다. 도구는 현재 상태도 먼저 백업하고 대상 ZIP을 검증한 뒤 전체를 되돌립니다.

    & 'Java 실행 파일 전체 경로' -jar .\InterfaceInstaller.jar 복원 '서버 전체 경로' '전체 백업 ZIP 경로' --서버종료확인

복원 후 시작 전에 파일을 확인하고, 접속 후 월드·잔액·집·NPC·땅·농사·도감·직업을 확인하세요. 해당 시점 이후 모든 변경이 함께 되돌아갑니다.

**가방만 복원할 때는 판매·도감 소비·요리·농장 거래와 함께 대조해야 합니다.** 이미 판매·소비한 아이템을 과거 가방에서 다시 지급하면 복제가 됩니다. 미결 거래는 확인 후 수동 정리하고 자동 재지급하지 않습니다. InventoryRollbackPlus는 설치하지 않습니다.

통합팩은 그대로입니다. [기존 1.2.1 안내](https://github.com/wjdtjddyd956-svg/akdlszmfovcm/blob/main/interface-update/README.md)의 팩을 사용합니다. 새 팩 요청이나 리소스팩 필수 설정을 추가하지 않습니다.
