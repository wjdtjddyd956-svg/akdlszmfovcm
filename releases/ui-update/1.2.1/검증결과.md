## 실제 서버와 UI에서 확인한 것

실제 네트워크에서 접속당 통합팩 요청1개를 확인했습니다. 거절 후 접속과 기본 메뉴를 유지했습니다. 팩 성공/실패 이벤트의 현재 메뉴 갱신은 실제 Paper에 상태 이벤트를 주입한 검사로도 확인했으며, 실제 다운로드·화면 확인과 구분했습니다.

가방의 기본 참나무3개만 표시하고 이름 바꾼8개·보조 손64개·장비 칸64개는 제외했습니다. 등록 가능 필터의 실제 슬롯과 클릭이 일치했습니다. 확인 전 보유3개·소비1개·실제 증가량이 표시됐고 취소 시 수량이 유지됐습니다. 중복 확인 패킷은1개만 소비해2개가 남았고 분야1/10·전체1/85로 갱신됐습니다. 등록 완료 클릭은 재소비하지 않으며 미보유 필터에서 등록된 원목이 제외됐습니다. 업적 남은9종·효과 상한·마을 수첩 복귀도 확인했습니다.

기존80종 완성 계정은 그대로 보존돼 상한에서 농작물 등록 확인에 추가 체력 증가를 약속하지 않았습니다. 미결 거래는 등록 대기·가능0종으로 표시되고 재시작 후에도 아이템을 자동 소비하지 않았습니다. 가방36칸이 가득 찬 상태에서도 원목2→1개만 소비하고 다른35스택2240개를 보존했습니다. 창조 모드와 권한 제한에서는 등록 가능으로 잘못 표시하거나 소비하지 않았습니다.

자동 검사 초기에 테스트 프로토콜의 UUID 응답과 잘못된 제목/참나무 부분 문자열 비교를 수정했습니다. 같은 localhost에서4계정 동시 접속은 기존 GP IP제한으로 끊겼으므로 보호 설정을 낮추지 않고 이전 테스트 계정을 종료한 뒤 순차 진행해 통과했습니다.

실제 Minecraft26.3에서는 기존 농작물 등록1개가 있던 합성 계정으로 쉬프트+F → 도감 → 숲과 채집 → 등록 가능 → 정품3개 표시 → 소비 확인 → 등록을 직접 클릭했습니다. 기본 원목2개가 남고 분야1/10(10%), 전체2/85가 됐습니다. 업적2/10·남은8종, 이동속도0.12%·상한3%, 체력20/최대20.02를 확인한 뒤 마을 수첩으로 돌아왔습니다. 기존 농장 등록 보상이 유지됐고 즉시 체력 회복은 없었습니다.

## 실제 Windows 적용과 보존

`ServerStop.cmd`로 Paper와 기존 관리자를 종료하고 `전체서버-20261111-153216-732.zip`을 생성·SHA-256 검증한 후 적용했습니다. 별도 폴더에 복원해636개 파일의 원본 해시를 확인했으며 새 파일이 복원 뒤 남지 않는 것도 확인했습니다. 설치 전·후464개 데이터/월드/비대상JAR 파일이 같았고, 경제 JAR는 동일 해시여서 교체하지 않았습니다. 이전 메뉴·도감·농사3개 JAR만 백업으로 옮기고 새3개와 CityTextures1개를 추가했습니다.

재시작 후 경제·농장·도감17테이블의 행 내용 해시가 모두 같고 두DB 무결성이 정상입니다. 플러그인16개가 각1개씩이며 테스트용 UIProbe·FarmProbe·CodexProbe·ViaVersion/ViaBackwards는 운영 서버에 없습니다. EssentialsX2.22.1-dev+28-f8724e2 본체/Spawn·Vault·GP·Prism·QuickShop·WE/WG·백업 관리자와 기존 메모리/인증 설정을 유지했습니다. 사용자 백업·DB·월드는 GitHub와 배포 ZIP에 넣지 않았습니다.

UI 적용 후에도 기존 Windows 관리자의 월드 포함 냉백업과 재시작을 실행했습니다. 15:38:56 백업 성공, ZIP CRC·SHA-256 사이드카·새5JAR 해시·두DB 무결성·농장 테이블·월드·CityTextures/ui.yml 포함을 확인했습니다. 상세는 backup-validation.json입니다. 현재 운영 서버만 다시 실행 중이며 테스트 서버와 테스트 클라이언트는 종료했습니다.

## 남은 범위

이 PC에서 앞선 팩 전환 중 Java25/27 일반 JVM의 LWJGL/FFM 호출에 EXCEPTION_ACCESS_VIOLATION이 발생했습니다. 서버 로그의 추방이나 플러그인 예외가 아닙니다. 기존 Java27의 -Xint 진단 실행에서는 새 통합팩과 위 실제 UI 흐름을 완료했습니다. **일반 런처/JVM 프로필의 팩 전환 안정성은 아직 확인되지 않았습니다.** 원래 클라이언트 라이브러리나 프로필을 교체하지 않았고 진단 모드를 이용자 기본값으로 강제하지 않았습니다.

10명 동시 부하, 모든 GPU/팩 조합·GUI 배율, 실제 운영 이용자 로그인, 강제 전원 차단·디스크 고장은 검증하지 않았습니다. 정상 종료/재시작과 오류 주입 검사를 이런 상황의 무조건 보장으로 확대하지 않습니다.
