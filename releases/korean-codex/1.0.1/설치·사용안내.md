# 아이템 도감·수집 업적 1.0.1 — Windows / Paper 26.3

기존 `korean-codex`의 80종·8개 분야·12업적 구현을 이어서 보완했습니다. 경제·직업·강화·집·땅·기존 메뉴 JAR를 교체하지 않고 **KoreanCodex JAR 하나만** 추가합니다. 기존 도감 DB가 있으면 등록·업적·개인 설정을 보존해 이전합니다.

## Windows 설치

1. 설치 ZIP을 **서버 폴더 밖**에 압축 해제합니다.
2. `설치하기.cmd`를 실행하고 `server.properties`가 있는 서버 폴더를 입력합니다.
3. 설치기가 JAR와 백업 도구의 SHA-256을 확인한 뒤 원래 **`ServerStop.cmd`를 실행**해 서버와 Windows 백업 관리자를 정상 종료합니다.
4. 서버의 모든 파일을 `tycoon-server-backups/전체서버-날짜.zip`으로 백업하고 내부 파일별 SHA-256 검사를 통과한 뒤 도감 JAR만 설치합니다. 기존 도감 JAR가 있으면 같은 백업 폴더의 `도감-교체전-*`에 보관합니다. 다른 플러그인 JAR와 설정을 덮어쓰지 않습니다.
5. 기존 `ServerStart.cmd`로 시작합니다. 콘솔의 KoreanCodex 1.0.1 활성화와 `/도감`을 확인하세요.

첫 기동에 `plugins/KoreanCodex/config.yml`과 도감 DB를 자동 생성합니다. 별도 설정 복사는 필요하지 않으며 기존 도감 설정 파일이 있으면 유지합니다.

기존 서버의 종료 스크립트가 필요하며 설치 중 다른 창에서 서버를 시작하지 마세요. 백업 폴더 자체와 재생성되는 `session.lock`·설치 잠금은 전체 백업에서 제외합니다. 실패하면 창에 표시한 오류를 확인하세요. JAR 파일만 수동 복사하는 절차보다 동봉 설치기를 사용하세요.

## 수집·확인·보너스

숲·농장·광물·바다·제작·네더·엔드·전리품 8개 분야에 각각 10종, 총 80종입니다. 기본 아이템을 등록 확인창에서 확인하면 **가방의 동일한 기본 아이템 1개**를 소비합니다. 등록은 UUID별로 한 번이며 아이템이 없어져도 기록과 보너스가 유지됩니다.

이름·설명·추가 마법·손상·커스텀 모델·커스텀 데이터가 있는 아이템은 등록 재료로 쓰지 않습니다. 장비칸과 보조 손도 제외합니다. 기본 마법 황금 사과의 원래 반짝임처럼 아이템 종류 자체의 성질은 추가 마법과 구분합니다. 특별한 물건 옆에 같은 종류의 기본 아이템이 있으면 **기본 아이템만** 소비합니다.

같은 분야의 일반 아이템을 기준으로 고급 2배·희귀 4배·전설 8배입니다. 모든 분야에 일반 기준 항목을 두었습니다. 네더의 별·겉날개·네더라이트 주괴는 전설입니다. 드래곤 알은 수집 대상·필수 완성 조건에서 제외했습니다. 귀한 물건도 확인창에 소비 1개, 희귀도와 실제 증가량을 표시하며 취소하면 소비하지 않습니다.

| 능력치 | 80종·12업적 전체 완성 상한 |
|---|---|
| 이동 속도 | +3% |
| 채굴 속도 | +6% |
| 최대 체력 | +2HP = 하트 1칸 |
| 공격력 | +0.5 |
| 방어력 | +1 |
| 공격 속도 | +2% |
| 넉백 저항 | +2%p |
| 행운 | +0.5 |

아이템 등록과 업적 보너스를 모두 합쳐도 이 상한을 넘지 않습니다. 10/30/50/80종 수집 업적 4개와 분야 완성 8개가 자동으로 달성·저장되고 추가 보너스를 줍니다. **[80종 아이템별 수치와 업적 추가 보상](아이템별보너스.md)**은 생산 JAR의 실제 계산 결과에서 생성한 표입니다. 체력의 수치 단위는 HP이며 2HP가 하트 1칸입니다.

이 상한은 도감이 더하는 수치입니다. 기존 속성 기본값·장비·물약·다른 플러그인의 수정자는 유지합니다. 비율 항목은 속성의 기본값에 비율을 더하며 다른 효과까지 포함한 최종 이동 거리·채굴 틱 수의 정확한 비율을 보장한다는 뜻은 아닙니다. 행운은 해당 바닐라 속성을 참조하는 전리품 판정에 사용합니다.

## 한글 명령과 메뉴

| 명령 | 기능 |
|---|---|
| `/도감` 또는 `/아이템도감` | 분야·등록 현황·아이템 목록 |
| `/도감 등록` | 손에 든 종류의 등록 확인창. 실제 재료는 가방의 기본 아이템 |
| `/업적` | 12개 업적과 달성·추가 보상 |
| `/도감효과` | 내 수집 보너스와 상한 |
| `/도감효과 켜기`, `/도감효과 끄기` | 개인 효과 설정. 재접속·재시작 후에도 유지 |
| 쉬프트+F → 도감/업적 버튼 | 기존 한글 수첩의 빈 20·26번 칸에 연결 |

기존 메뉴의 다른 버튼을 덮어쓰지 않습니다. 해당 칸에 이미 다른 기능이 있으면 명령어로 이용하세요. `plugins/KoreanCodex/config.yml`의 `메뉴-연결: false`로 연결을 끌 수 있습니다. 등록과 효과는 생존·모험 모드에서 사용합니다. `효과-사용: false`는 서버 전체 도감 효과를 끄며 개인 설정과 기록은 보존합니다. 설정 파일을 바꾸기 전 원본을 복사하고 변경 후 정상 재시작하세요.

도감 효과는 도감 전용 이름 공간의 **임시 속성 수정자**로 적용합니다. 반복 동기화·로그인·사망 후 재생성·월드 이동에서 같은 키가 쌓이지 않습니다. 체력 보너스를 얻거나 껐다 켤 때 현재 체력을 회복시키지 않습니다. 최대 체력이 줄면 현재 체력이 새 최대치를 넘는 부분만 줄입니다.

## 운영자 조회·확인 대기

일반 권한 `koreancodex.use`는 기본 허용, 운영 권한 `koreancodex.admin`은 기본 OP입니다. 일반 계정에 OP·운영 권한을 주지 마세요.

```text
/도감관리 조회 닉네임
/도감관리 거래
/도감관리 번호 거래번호
/도감관리 완료 거래번호 확인
/도감관리 취소 거래번호 확인
/도감관리 표식해제 닉네임 확인
/도감관리 백업
```

등록은 예약 기록 → 소비 전 플레이어 저장 → 아이템 1개 소비·플레이어 저장 → SQLite 등록 확정 순서입니다. 소비 전후 가방 해시, 원본 슬롯·스택 수량, 저장 단계를 기록합니다. 거래의 `amount`는 **소비 전 스택 수량**이며 실제 등록 소비량은 항상 1개입니다.

저장 오류나 도중 종료로 결과가 불확실하면 확인 대기로 잠급니다. **자동 재소비·환불·재지급·확정을 하지 않습니다.** `완료`는 실제 소비를 확인하고 등록만 확정하며, `취소`는 소비가 없거나 운영자가 이미 복원했음을 확인한 후 잠금을 정리합니다. 두 명령 모두 가방을 자동 수정하지 않습니다. 저장소 오류로 새 등록 전체가 중지됐다면 원인을 해결하고 기록을 정리한 뒤 정상 재시작하세요.

플레이어 PDC `koreancodex:pending_registration`에는 거래 번호와 BEFORE/CONSUMED가 저장됩니다. DB에 없거나 다른 UUID의 거래를 가리키는 표식도 별도 `marker_reviews` 확인 대기 기록으로 저장해 재소비를 차단합니다. 운영자가 실제 파일과 가방을 확인한 후 `표식해제`로 이 잠금만 해제할 수 있습니다. 해제 이력은 보존하며 아이템이나 등록을 자동 지급하지 않습니다.

## 백업·복원

도감 기록은 `plugins/KoreanCodex/도감.db`에 있습니다. 실행 중 `도감.db`만 단순 복사하지 마세요. `/도감관리 백업`은 SQLite의 일관된 도감 전용 스냅샷을 `plugins/KoreanCodex/백업`에 만듭니다. 경제 DB만 백업하는 `/서버백업`과 별개입니다.

원래 Windows 백업 관리자는 정상 종료 후 `plugins` 전체를 복사하므로 도감도 월드·플레이어·다른 플러그인과 같은 시점에 포함됩니다. 주기·보관 개수·위치는 기존 `life-tools/backup.json`을 유지합니다. `/백업 상태`, `/백업 지금`과 `life-control/status.txt`, `backup.log`로 성공·실패를 확인합니다.

설치 전 **전체 백업 ZIP**을 검증·복원하려면 먼저 `ServerStop.cmd`로 서버와 관리자를 종료하고, 배포 폴더에서 실행합니다.

```text
java -Dstdout.encoding=UTF-8 -jar 전체백업도구.jar 검증 "전체서버-날짜.zip"
java -Dstdout.encoding=UTF-8 -jar 전체백업도구.jar 복원 "서버폴더" "전체서버-날짜.zip" --서버종료확인
```

복원 전에 현재 서버도 다시 백업하며, 새 파일이 옛 복원에 섞이지 않도록 현재 최상위 폴더를 별도 보관합니다. 완료 후 기존 `ServerStart.cmd`로 시작합니다. 전체 백업 폴더는 자동 삭제하지 않으므로 여유 공간을 확인하고 다른 디스크에도 복사하세요.

기존 예약 `life-*.zip`은 형식이 다릅니다. `.sha256` 파일과 함께 보관하고 종료 후 기존 `life-tools/Restore-LifeBackup.ps1 -Archive "예약백업.zip" -ServerDirectory "서버폴더"`로 복원하세요. 도감 DB만 과거로 되돌리면 소비한 아이템·등록 기록 시점이 어긋나므로 월드·플레이어·플러그인을 같은 시점으로 복원하는 방식을 우선합니다.

검증 결과와 실제 적용 여부는 동봉 `검증결과.md`에 구분해 기록합니다. 테스트 보조 CodexProbe·프로토콜 어댑터·RCON·오프라인 인증은 운영 서버에 설치하지 않습니다.
