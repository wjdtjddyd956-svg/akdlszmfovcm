# 2.0.1 검증 결과 — 2026-11-11 Windows

실제 Windows 서버의 설치 JAR를 먼저 조사했습니다. 저장소에 2.0.0이 있어도 실제 서버는 KoreanEconomy/KoreanMenu 1.2.0이었습니다. 기존 2.0 구현을 이어서 수정했고, 서버·백업 관리자를 정상 종료한 전체 백업 후 **운영 서버에 적용했습니다**. 모든 기능을 실제 운영 이용자로 플레이 완료했다는 뜻은 아닙니다.

## 실제 운영 서버에서 확인

- Paper 26.3 build 238, 기존 JDK 27, 관리자 최대 힙 2048MB 유지. 자체 4개 플러그인은 실제 설치된 `paper-api-26.3.build.238-stable.jar`로 새로 컴파일했습니다. 파일별 소스 해시와 API 해시는 `windows-build.json`에 있습니다. 테스트용 Bukkit 클래스는 배포하지 않습니다.
- KoreanEconomy **2.0.1**, KoreanMenu/KoreanCommands/KoreanPackSetup **2.0.0** 활성화와 정상 부팅. EssentialsX/Spawn **2.22.1-dev+28-f8724e2**, GP **16.18.8**, Prism **4.5**, QuickShop **6.3.0.4**, Vault, WorldEdit/WorldGuard/NBTAPI 유지. 26.3 미지원 2.22.0으로 내리지 않았습니다.
- 설치 전 전체 ZIP `전체서버-20261111-123119-492.zip` 약 355MB. 정상 종료와 월드 저장을 로그·잠금으로 확인한 후 생성했고, 내부 모든 파일의 SHA-256 검증을 통과했습니다.
- **실제 백업을 별도 폴더로 복원한 612개 서버 파일이 원래 해시와 일치**했습니다. 복원 대상에 추가한 새 파일이 옛 복원에 섞이지 않는 것도 검사했습니다. 운영 서버 자체를 옛 상태로 되돌린 것은 아닙니다.
- 설치 후 첫 부팅 전에 월드·모든 기존 플러그인 데이터/설정·Windows 관리자 등 **448개 파일이 백업과 동일**함을 대조했습니다. 기존 계정에 1,000원을 추가 지급하지 않았습니다.
- 기존 잡화상인 `ALL`과 임무 NPC `QUEST`를 유지하고 스폰 주변에 주방장 `(-16.5,75,-17.5)`, 농부 `(-13.5,76,-18.5)`, 광물상 `(-10.5,76,-16.5)`을 추가했습니다. 지형을 바꾸지 않고 바닥·두 칸의 빈 공간을 검사했습니다. NPC 5명의 PDC·이름·좌표가 정상 종료 후 월드 엔티티 파일에 저장된 것을 읽어 확인했습니다.
- 원래 관리자의 `/백업 지금` 요청으로 저장·정상 종료·차가운 스냅샷·별도 압축·재시작·성공 기록을 확인했습니다. 12:37과 12:43 백업이 성공했습니다. 한글 예고가 Windows 입력 인코딩에 따라 깨지는 부분만 ASCII JSON 이스케이프로 보완했습니다. 관리자 교체나 주기/보관/경로/메모리 옵션 초기화를 하지 않았습니다.
- 수정된 예고와 함께 마지막 백업 후 **12:43:36 정상 기동, 12:43:37 백업 성공**. 기존 `ServerStart.cmd`와 `ServerStop.cmd`를 그대로 사용합니다. 테스트 어댑터·오프라인 인증·RCON·LifeTest를 운영 서버에 설치하지 않았습니다.

설치 시 두 번째 전체 백업 `전체서버-20261111-124022-692.zip`도 만들었습니다. 서버의 `tycoon-server-backups`와 옆 `*-backups` 폴더를 삭제하지 않았습니다. 백업 파일과 사용자 데이터는 GitHub에 올리지 않습니다.

## 실제 Paper 복사본 검사

운영 폴더와 별도인 복사본에서 같은 Paper/Essentials/Vault/GP/Prism으로 접속·거래했습니다. 봇 접속은 테스트 전용 ViaBackwards를 거친 26.1 프로토콜이며 순정 26.3 화면 검증과 구분합니다. 성공한 **35개 검사 그룹**의 원본은 `tools/runtime-checks/`에 있습니다.

| 범위 | 실제 확인 내용 |
|---|---|
| 돈·기존 명령 | 신규 1000원, 두 온라인 계정 송금, 일반 계정 돈 생성 거부, 집 저장·집 이동·스폰 이동 |
| 요리·상점 | 재료 9개→빵 3개, 재료 부족 거부, 실제 식별 요리만 NPC 매입, 일반 빵 거부, 설정 가격·한도 적용 |
| 중복·중단 조건 | 같은 옛 메뉴의 동시 클릭은 1회 처리, 구매 잔액 부족·한도 초과 시 돈/아이템 유지, 도구 교체·NPC 거리 이탈 시 거래 거부 |
| 강화 | 1단계 비용 1000원과 강화 PDC·마법 적용, 부족한 잔액에서 다음 강화 거부, 0% 설정 실패 시 비용만 사용하고 도구 유지 |
| 직업·임무 | 농부 수확 적립 2원과 중복 수령 방지, 1.2 광부 이전, 자연 광석 3원·배치 이벤트 광석 제외, NPC 임무 수락·밀 32개 회수·120원 1회 지급 |
| 재시작 | 돈·가방·직업·강화 데이터·NPC·완료 임무·당일 판매량 유지, 재지급 거부 |
| 권한·땅 | 운영자 명령 6종 한국어 거부, GP 소유자 확인·타인 해제/파괴 거부·상자 초대·권한 회수 |
| 기록·복구 | 실제 Prism 블록/상자 조회·미리보기·적용으로 광석과 꺼낸 다이아 복원 |
| 백업 | Windows 관리자 예고가 실제 접속자에게 올바른 한국어로 수신, 정상 종료·압축·다시 시작·성공 기록 |

GP 땅 생성·배치 광석 표식·상자 열기는 테스트 보조 API를 사용했고, 클릭·파괴·Prism 복구는 실제 서버에서 처리했습니다. 금 삽의 네이티브 두 모서리 지정 전체 조작을 이번에 완료한 것으로 계산하지 않습니다.

순정 Minecraft **26.3** 테스트 클라이언트로 실제 복사본에 접속해 **쉬프트+F → 한글 수첩 → 요리 메뉴**, **사람형 NPC 우클릭 → 요리 매입 창**을 화면으로 확인했습니다. 서버/메뉴의 기본 음식 아이콘을 사용했습니다.

## SQLite·장애 주입·설치 도구

- **121개**: 실제 SQLite 파일 DB의 도메인 73, 거래 장애 주입 15, 기존 1.2 이전 33. 최신 Windows용 생산 JAR의 SQLite 드라이버로 실행했습니다.
- 경제 제공자가 지급 후 예외를 내는 경우, 환불 거부/예외, 아이템 적용·복구 실패, 최종 DB 실패, 재접속/재시작 시 미결 거래, 당일 한도·임무 중복·1.2 적립금/기록 보존 검사. 경제 제공자·인벤토리는 **테스트 대역**입니다. 실제 서버를 강제 종료해 재현했다고 표시하지 않습니다.
- **25개**: 실제 Windows 파일 시스템에서 설치·재설치·SHA 손상·경로 탈출·session.lock 잠금·전체 복원·이전 파일 제거·미결 거래 거부·Essentials 버전 불일치 거부. 플러그인 메타데이터는 테스트 fixture이며 런타임 검증과 별개입니다.
- Windows PowerShell 설치기를 실제 복사본과 운영 서버에서 실행했습니다. ZIP 무결성·내장 설정·JAR 소스 출처·Paper/MockBukkit 클래스 미포함을 검사했습니다. SQLite 네이티브 라이브러리는 원본 Windows DLL과 라이선스를 유지하고 다른 OS DLL만 제외해 Windows용 경제 JAR를 약 2.7MB로 줄였습니다.

재빌드:

```powershell
python tools/build_tycoon_windows.py --server "Paper 서버폴더" --jdk "JDK 폴더"
$env:TYCOON_JAVA="JDK 폴더\bin\java.exe"
python tools/test_installer.py
python tools/package_tycoon_windows.py
```

기존 2.0 JAR의 확인된 SQLite/설정 리소스를 의존성으로 재사용하고 자체 클래스는 전부 다시 컴파일합니다. 원래 JAR 해시도 검사합니다. API 버전 기본값은 `26.3.build.238-stable`이며 오래된 222 API가 함께 있어도 선택하지 않습니다.

## 남은 확인과 알려진 한계

- 운영 서버의 실제 Microsoft 인증 이용자로 전체 거래·집·낚시를 직접 플레이하지 않았습니다. 위 플레이 검사는 별도 Paper 복사본입니다.
- 10명 동시 농장/월드 생성 부하·장시간 경제 밸런스·실제 낚싯대 투척부터 랜덤 어획까지의 전 과정·임무 종류 전체의 게임 플레이·모든 요리 해금 레벨·강화 확률의 장기 분포·선택 리소스팩 시각 검증은 남았습니다. 구현과 검증 범위를 구분합니다.
- 전원 차단·외부 Vault 저장소와 플레이어 NBT·SQLite를 아우르는 원자성은 보장하지 않습니다. 불확실한 거래는 REVIEW로 남기고 자동 재지급하지 않습니다. 실제 결과 확인 후 운영자가 기록을 정리해야 합니다.
- 이번에 새로 MockBukkit 전체 검사를 돌렸다고 표시하지 않습니다. 이전 2.0.0의 모의 검사 결과는 그 버전 보고서에 보존했습니다. 이번 후속 검증은 실제 API 컴파일·SQLite·Windows·Paper 실행을 우선했습니다.
- Paper build 238이 최신보다 10빌드 뒤라는 알림, Windows에서 선택 프로파일러 엔진을 쓸 수 없다는 알림, QuickShop 세금 계정 생성 경고는 숨기지 않았습니다. 요청한 build 238을 임의로 업데이트하지 않았으며 플러그인 기동 실패나 Essentials의 26.3 미지원 오류는 확인되지 않았습니다.
