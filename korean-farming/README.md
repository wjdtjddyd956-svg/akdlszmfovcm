# 도시 농장 1.0.0

Paper 26.3 / Java 25용입니다. **KoreanEconomy 2.0.2 · KoreanFarming 1.0.0 · KoreanCodex 1.1.0**을 함께 설치합니다. 기존 생활타이쿤 2.0.1·도감 1.0.1과 데이터가 있는 서버에 추가하는 업데이트입니다. 도감 1.0.1의 DB 스키마 2·알 수 없는 저장 표식 보호·희귀도·보상을 유지합니다.

딸기·토마토·옥수수·쌀·오이의 씨앗 구매 → 심기 → 4단계 성장 → 수확 → 농부 숙련도·적립금 → 전용 요리 → NPC 매입 → 도감 등록을 연결합니다. 모든 이용자 명령어와 안내는 한국어입니다.

| 작물 | 첫 수확 | 수확량 | 씨앗 구매 | 수확물 판매 | 수확 후 |
| --- | --- | --- | --- | --- | --- |
| 딸기 | 8분 | 2~4개 | 40원 | 8원 | 25%부터 재성장 |
| 토마토 | 10분 | 2~4개 | 35원 | 7원 | 25%부터 재성장 |
| 옥수수 | 15분 | 2~4개 | 30원 | 10원 | 작물 제거, 씨앗 1개 반환 |
| 쌀 | 10분 | 3~5개 | 20원 | 5원 | 작물 제거, 씨앗 1개 반환 |
| 오이 | 9분 | 2~4개 | 30원 | 6원 | 25%부터 재성장 |

성장 시간은 **서버가 켜져 있고 작물 청크가 로드된 상태에서의 시간**입니다. 10초 단위로 성장하며 서버 종료·청크 언로드 시간은 따라잡지 않습니다. 경작지는 물로 젖어 있어야 하며, 작물 칸 밝기는 9 이상, 위쪽 2칸은 비어 있어야 합니다. 밤에는 횃불을 설치하세요. 뼛가루로 성장 시간을 건너뛰지 않습니다.

한 사람당 32그루, 서버 전체 256그루입니다. 작물당 로드된 청크에만 ItemDisplay 1개와 Interaction 1개를 생성합니다. 최대 512개 엔티티라는 설계 한도이며 10명 동시 부하 테스트 결과는 아닙니다. 엔티티는 월드에 저장하지 않고 DB에서 재생성합니다. 모드·ItemsAdder·Oraxen·Citizens는 필요하지 않습니다.

## 설치

1. ZIP을 **서버 폴더 바깥**에 풉니다. 기존 `ServerStop.cmd`로 서버와 자동 백업 관리자를 정상 종료합니다. 없으면 콘솔에서 `stop`하고 완전히 종료합니다.
2. 압축을 푼 폴더의 `Install-Farming.cmd`를 실행하고 `server.properties`가 있는 서버 폴더를 지정합니다. 설치기는 종료 확인을 받은 뒤 잠금과 JAR 해시·버전을 검사하고, 전체 서버를 백업·검증한 후 플러그인 3개를 이름으로 교체합니다. **플러그인 데이터 폴더·잔액·직업·땅·도감 기록을 삭제하지 않습니다.**
3. 기존 `ServerStart.cmd`로 시작합니다. `/plugins`에 KoreanEconomy 2.0.2, KoreanFarming 1.0.0, KoreanCodex 1.1.0이 켜졌는지 확인합니다. `/reload`는 사용하지 않습니다.
4. 접속 시 농장 통합 리소스팩 다운로드를 허용합니다. 직접 설치하려면 `resourcepacks/CityEconomy-Farming-26.3-1.1.0.zip`을 게임의 리소스팩 폴더에 넣고 활성화한 뒤 `/농사 팩확인`을 입력합니다. 이 확인은 수동 설치를 사용자가 확인하는 명령이며 클라이언트 파일을 자동 검사하지 않습니다.
5. `/농사`, 쉬프트+F → **커스텀 농사**, 기존 농산물/잡화 NPC → **농장 상점**을 사용합니다.

수동 설치: 전체 백업을 만든 뒤 `plugins/` 안의 새 JAR 3개를 복사하고 이전 KoreanEconomy·KoreanCodex·KoreanFarming JAR만 서버 밖으로 옮겨 같은 이름의 플러그인이 한 개씩 남게 합니다. 기존 데이터 폴더는 유지합니다. Vault·Essentials·QuickShop·GriefPrevention·Prism·WorldEdit·WorldGuard·도시팩 보조 플러그인은 이 업데이트에서 교체하지 않습니다.

기존 1.2 서버나 더 새로운 미확인 버전을 설치기로 덮어쓰지 않습니다. 별도 `KoreanFarming/config.yml`이 이미 있다면 기존 설정을 보존합니다. 팩이 바뀌면 아래 주소와 SHA1도 함께 맞춰야 합니다.

## 팩 구성

- 기본 통합팩: 기존 도시 아이콘 32개 + 씨앗·수확물·요리 15개 + 작물 성장 모델 20개. 기본 Minecraft 건축 블록 텍스처를 바꾸지 않습니다.
- Complete: 기본 통합팩 + 기존 도시 건축 재질 8개. 이 팩을 수동 적용할 때에는 `resourcepack-validation.json`에서 추측하지 말고 실제 Complete ZIP의 SHA1을 계산해 설정에 넣거나 `/농사 팩확인`을 사용하세요.
- 서버 설정: `plugins/KoreanFarming/config.yml` → `리소스팩.주소` / `SHA1`. 기본 주소는 이 저장소의 농장 통합팩 ZIP입니다. HTTPS로 직접 ZIP을 내려받을 수 있어야 합니다. GitHub가 차단된 이용자는 수동 설치를 사용하세요.
- 팩을 거절해도 접속은 유지합니다. 새 작물 표시·심기·수확은 팩 준비 후 사용합니다. 기본 도시팩만으로는 새 작물이 표시되지 않습니다. 자동 다운로드는 `접속시-요청: false`로 끌 수 있습니다.
- `농작물-미리보기.png`는 생성 에셋 구성표이며 실제 게임 화면 캡처가 아닙니다.

NPC 거래는 5블록 이내에서만 가능합니다. 좌클릭 1개, 쉬프트 클릭 16개, 우클릭 64개입니다. 수확물·요리 **품목별·개인별 하루 매입 한도는 64개**이며 경제 플러그인의 날짜/시간대를 사용합니다. 씨앗은 구매만 가능합니다. 이름만 같은 기본 아이템·변조한 수확물·씨앗은 수확물 도감이나 판매 대상으로 인정하지 않습니다. 무게·별도 화폐·별도 잔액을 만들지 않습니다.

농부를 선택했다면 수확 1회에 숙련도 2와 기본 2원 적립금을 얻습니다. 기존 농부 보상 설정·하루 숙련도 250·직업 적립 한도 300원과 공유합니다. 다른 직업은 수확할 수 있지만 농부 경험치·적립금은 받지 않습니다. `/직업`에서 적립금을 받습니다. 수확물 개수만큼 보상을 중복 지급하지 않습니다. 미결 거래 수동 확정 시에는 확정 시점의 날짜·현재 경제 설정으로 한도를 적용합니다.

## 도감 확장

기존 80종의 ID·등록 기록·보너스·12개 업적·능력치 상한은 유지합니다. **도시 농장 5종을 추가해 85종·13개 업적**이 됩니다. 수확물 1개를 소비해 한 번만 등록하며 씨앗·요리·기본 사과 등은 농작물 등록 대상이 아닙니다.

각 수확물 등록: 최대 체력 **+0.02 HP**. 5종 완성: 이동 속도 **+0.1%**. 기존 전체 상한(체력 +2 HP, 이동 +3% 등)은 그대로입니다. 이미 상한에 도달했다면 그 능력치가 추가로 증가하지 않습니다. 즉시 회복·반복 등록·접속 시 효과 중첩은 없습니다. 농장 플러그인이 없으면 새 5종을 소비 등록할 수 없고 기존 도감은 사용할 수 있습니다.

## 보호·저장·복구

- 경제와 같은 `plugins/KoreanEconomy/생활경제.db`의 `farm_plots` 테이블을 사용합니다. 기존 DB 스키마 버전과 이전 테이블을 초기화하지 않습니다. `/서버백업` 경제 DB 스냅샷에 농장도 포함됩니다. 별도 도감 DB는 `/도감관리 백업` 또는 전체 서버 백업으로 보관하세요.
- 기본 땅 보호 + 설치되어 있으면 WorldGuard·GriefPrevention 권한을 검사합니다. 보호 연동 실패는 허용으로 취급하지 않습니다. GP 16.18.8의 공식 `allowBuild(Player,Location,Material)` API와 WG 7.0.21의 `RegionQuery.testBuild`를 사용합니다. 타 플러그인이 취소한 상호작용은 다시 허용하지 않습니다.
- 작물은 소유자와 운영자만 수확·회수할 수 있습니다. 땅 건축 허가도 함께 필요합니다. 설치 후 땅 권한이 바뀌면 거래 시 재검사합니다. 경작지·작물 칸·위 한 칸을 파괴·유체·피스톤·폭발·짓밟기에서 보호합니다. WorldEdit 등 관리 도구가 직접 바꾼 지형은 자동 복원하지 않습니다. 성장 조건을 복구하거나 작물을 회수하세요.
- 공유 경제 거래 처리기로 Vault·가방 변경·작물 좌표 예약·직업 보상을 연결합니다. 심기는 좌표를 먼저 예약하고, 수확은 작물/회차를 먼저 잠급니다. 수확량은 한 번만 정해 기록합니다. 확정된 수확과 직업 보상은 같은 SQLite 거래로 저장합니다.
- Vault·플레이어 데이터·SQLite는 단일 원자적 저장소가 아닙니다. 중간 종료 또는 결과 불명 거래는 `REVIEW` 상태로 잠그고 자동 재지급·재수확하지 않습니다. 실제 아이템·잔액을 확인해야 합니다.

운영자: `/농사관리 목록`, `/농사관리 거래`, `/농사관리 번호 거래번호`, `/농사관리 완료 거래번호 확인`, `/농사관리 취소 거래번호 확인`. 완료는 실제 아이템·돈 처리가 끝난 것을 확인한 뒤 작물/보상 기록만 확정합니다. 취소는 처리되지 않았거나 수동 복구한 것을 확인한 뒤 예약만 해제합니다. 이 명령은 돈·아이템을 다시 지급하지 않습니다. 농장 거래는 `/경제기록`에서 확정하지 못하도록 구분합니다. 자료 복원은 같은 시점의 전체 서버 백업을 사용합니다.

`koreanfarming.use`는 기본 허용, `koreanfarming.admin`은 운영자 기본 허용입니다. 가격·작물 수·시간은 현재 소스의 `FarmRules`에 고정되어 있습니다. 임의 설정값 변경으로 밸런스를 깨거나 진행 중인 작물 상태를 잘못 해석하지 않도록 이 버전에는 실행 중 변경 기능을 넣지 않았습니다.

## 검증 범위

수정하지 않은 실제 Paper 26.3 df120fd API와 Java 25 컴파일러로 빌드하고 실제 SQLite JDBC·MockBukkit 26.3으로 거래·성장·수확·DB 재시작·백업·가방 실패·보상 롤백·NPC/메뉴/도감 연결을 검사합니다. MockBukkit에 없는 플레이어 NBT 저장은 호출 횟수/실패 주입으로, 엔티티 기본 표시 속성은 테스트 전용 MockBukkit 하위 클래스로 보완합니다. 실제 서버 NBT 내구성·네트워크 표시·작물 타격 판정·클라이언트 렌더링·GP/WG 실서버 연동·Windows 실행·10명 부하는 여기에서 확인하지 못했습니다. 이 업데이트를 사용자 Windows 서버에 설치한 상태는 아닙니다. 상세 수치는 배포 폴더의 `validation.json`에 기록합니다.
