# 생활 타이쿤 2.0 · Paper 26.3

띵타이쿤에서 참고한 직업·생산·성장 흐름을 10명 규모로 만든 자체 플러그인입니다. 자체 코드·기본 아이템을 사용합니다. 한글 채팅 변환 기능은 없습니다.

## 이미 사용 중인 1.2.0에서 업그레이드

현재 설치한 1.2.0의 GriefPrevention 땅·Prism DB·Windows 전체 자동 백업 관리자를 그대로 사용합니다. `/기록조회`, `/복구`, `/백업 상태`, `/백업 지금`도 유지합니다. 아래 새 버전의 실제 서버 접속 검증은 이전 1.2 검증과 별개입니다.

- 먼저 기존 `ServerStop.cmd`로 **서버와 백업 관리자를 함께 종료**하세요. 콘솔 `stop`만으로 관리자까지 종료됐다고 간주하지 않습니다.
- 기존 26.3 지원 EssentialsX 본체·Spawn 버전이 일치하면 그대로 재사용하며 새 CI 다운로드가 필요하지 않습니다.
- `생활기록/UUID.properties`의 직업·적립금·레벨 진행도·오늘 매입량·오늘 받은 임무를 SQLite로 한 번 가져옵니다. 원본 파일과 데이터를 지우지 않습니다. 1.2에서 받은 임무는 그날 `/임무` 하단의 **이전 임무**에서 원래 목표·보상으로 마칠 수 있습니다.
- 기존 직업 적립금은 새 `/직업` 금괴 버튼에서 받습니다. 농부·광부·낚시꾼의 활동당 적립과 하루 보상 한도 설정도 계속 사용합니다. 기존 직업 레벨은 새 1~5 단계 안에서 대응시켜 진행률을 가져오고 원래 활동 수는 원본과 가져오기 기록에 보존합니다.
- 1.2 미결 거래가 있으면 설치를 거부합니다. 기존 버전에서 실제 잔액·가방을 확인하고 `/경제거래 UUID 확인|완료|취소`로 정리한 뒤 다시 설치하세요. 새 버전에서 자동 재지급하지 않습니다.
- 업그레이드 후에는 기존 `ServerStart.cmd`로 켜면 전체 예약 백업도 계속 사용합니다. 이전 JAR만 되돌리지 말고, 되돌릴 때는 **월드·잔액·플러그인 데이터를 함께** 전체 백업으로 복원하세요.

## 설치

1. GitHub의 `releases/tycoon-2.0/생활타이쿤-통합설치-2.0.0.zip`을 받아 **서버 폴더 바깥**에 압축을 풉니다. 새 ZIP을 풀 때 이전 압축 해제 폴더에 덮어쓰지 마세요.
2. 1.2 서버라면 `ServerStop.cmd`로 서버·관리자를 종료합니다. 관리자를 쓰지 않는 서버는 콘솔 `stop` 후 Java가 완전히 종료될 때까지 기다립니다. 설치·백업·복원 중 서버를 다시 켜지 마세요.
3. `설치하기.cmd`를 실행하고 `server.properties`가 있는 폴더를 입력합니다. 기존 경로 예: `C:\Users\wjdtj\Downloads\버킷-실행파일-1\버킷-실행파일`.
4. 설치 도구가 기존 EssentialsX 본체·Spawn의 같은 버전과 26.3 지원 식별자를 검사해 재사용합니다. 없거나 미지원이면 공식 같은 개발 빌드를 받습니다. 다운로드·검증 실패 시 서버 JAR는 교체하지 않습니다. EssentialsX 2.22.0은 포함하지 않습니다.
5. 파일 검증 → **전체 서버 백업** → 같은 플러그인 이름의 기존 JAR 이동 → 새 JAR 설치 순서로 진행합니다. 기존 월드·Essentials 유저 잔액·집·스폰·보상 기록·설정 폴더는 지우지 않습니다. 이전 전체 백업을 보관할 디스크 공간이 필요합니다.
6. 서버를 실행하고 `/플러그인목록`, `/경제팩설정`, `/경제안내`, `/직업`을 확인합니다. 일반 이용자 권한으로 송금·집·스폰도 확인하세요. `/reload` 대신 `stop` 후 재실행합니다.

새 JAR 8개: KoreanEconomy, KoreanMenu, KoreanCommands, KoreanPackSetup, Vault, QuickShop-Hikari, Essentials, EssentialsSpawn. 기존 WorldEdit·WorldGuard 등 다른 플러그인은 유지합니다. GriefPrevention이 활성화되어 있으면 `/땅보호`와 기존 한글 땅 별칭도 기존 GriefPrevention을 사용합니다. 기존 땅을 새 청크 보호로 자동 변환하지 않습니다.

Windows 실행기와 실제 Paper 서버 접속은 이 클라우드에서 실행하지 못했습니다. 생성된 JAR를 Windows 서버에 원격으로 넣은 상태도 아닙니다. 검증 범위는 동봉한 `validation.json`에 기록했습니다.

## 첫 마을 설정

운영자 권한으로 평평하고 빈 11×5 공간 가운데 서서 `/마을설치`를 읽은 뒤 `/마을설치 확인`을 입력하면 잡화·농산물·광물·요리·임무 NPC 5명을 배치합니다. 블록은 변경하지 않습니다. 공간이 좁거나 기존 상인이 주변에 있으면 개별 배치하세요.

```text
/상인 생성 잡화상인 전체
/상인 생성 농부 농산물
/상인 생성 광물상 광물
/상인 생성 주방장 요리
/상인 생성 마을이장 임무
/상인 목록
/상인 삭제
```

마지막에 `주민`을 붙이면 주민형으로 생성합니다. 기본은 Paper 26.3의 사람형 MANNEQUIN입니다. 상인은 우클릭해 이용하며, 상인에게서 멀어지면 거래하지 않습니다. 일반 주민은 상점으로 바꾸지 않습니다. `/상인 삭제`는 가장 가까운 자체 NPC 하나만 지웁니다.

## 이용자 기능

| 명령어 | 동작 |
| --- | --- |
| 쉬프트+F, `/메뉴` | 한글 마을 수첩 |
| `/직업` | 농부·광부·낚시꾼 선택 / 직업별 숙련도 1~5 |
| `/요리` | 레벨에 맞는 요리 10종, 화면의 재료로 제작 |
| `/강화` | 주 손의 도구 강화, 비용·확률을 읽고 클릭 |
| `/임무` | 하루 3개 수락, 진행·납품 후 보상 수령 |
| `/땅보호` | 청크 단위 땅 생성·인접 확장·초대 안내 |
| `/일일보상` | 한국 날짜 기준 하루 200원 |
| `/돈`, `/송금 닉네임 금액` | 같은 Vault 잔액 조회·송금 |
| `/집저장`, `/집`, `/스폰` | Essentials의 기존 집·스폰 |
| `/거래소` | QuickShop 유저 상점 안내 |

직업 활동 보상은 기존 설정(농부 2원·광부 3원·낚시꾼 5원, 기본 하루 300원)으로 적립되며 `/직업` 금괴에서 받습니다. 돌은 숙련도만 주고 자연 광석은 직업 적립도 줍니다.

직업 첫 선택은 무료, 변경은 200원이며 30분 간격입니다. 숙련도는 직업별로 유지하며 하루 최대 250을 얻습니다. 농부는 다 자란 작물, 광부는 자연 돌·광석, 낚시꾼은 실제 낚시에서 얻습니다. 설치·피스톤 이동 블록 재채굴은 광부 숙련도에서 제외합니다. 관리 도구·다른 플러그인으로 지형을 수정한 경우까지 자연 지형임을 증명하지는 못합니다. 초기 경험치 기준은 0/100/300/600/1000입니다.

서버 원재료 매입은 **기존 설정의 품목별 개인 하루 한도**를 유지합니다(기본 밀 128, 다이아몬드 12개). 완성 요리는 요리별 한도가 있습니다. 요리는 마을 주방에서 만든 식별 데이터가 있는 물건만 매입하며 기본 음식·다른 플러그인의 음식은 받지 않습니다. 재료로는 이름·마법·설명이 없는 기본 아이템만 사용합니다. 가방이 부족하면 재료를 먼저 없애지 않습니다. 장비·보조 손은 거래하지 않습니다.

강화는 곡괭이·도끼·삽·괭이·낚싯대에 가능합니다. 단계 1~5 비용은 1,000/2,500/5,000/8,000/12,000원, 성공률은 100/85/70/55/40%입니다. 실패하면 비용만 사용하고 파괴·단계 하락은 없습니다. 성공하면 단계에 맞는 효율 또는 미끼와 내구성 마법을 적용하되 기존 더 높은 마법은 낮추지 않습니다. 낚싯대 4~5단계는 내구성 2~3으로도 성장합니다. 강화 창을 연 후 손에 든 도구가 바뀌면 진행하지 않습니다.

**기존 GriefPrevention 서버에서는** 금 삽으로 지정한 땅, 상자초대·회수·해제를 그대로 사용합니다. `/땅보호`에서 안내를 확인하세요.

**GriefPrevention이 없는 새 서버에서는** 첫 땅 16×16 청크 한 개는 무료, 이후 한 개당 2,500원, 최대 3개이며 기존 땅과 한 변이 붙어야 합니다. 모든 높이를 보호합니다. `/땅보호 생성 확인`, `/땅보호 확장 확인`, `/땅보호 초대 닉네임`, `/땅보호 추방 닉네임`, `/땅보호 권한`, `/땅보호 포기 확인`을 사용합니다. 초대는 내 모든 땅의 건축·상자 권한입니다. 포기 시 환불·무료 혜택 재지급이 없습니다. 운영자만 `koreaneconomy.land.bypass`로 우회합니다. WorldGuard 관리 영역이 있는 청크는 개인 소유로 만들지 않습니다. 다른 플러그인이 막은 행동을 강제로 허용하지 않습니다.

## 운영자 기록·백업

- `/경제기록 대기`: 처리 도중 중단돼 확인이 필요한 거래입니다. 기존 Vault 잔액과 가방을 확인하세요.
- `/경제기록 조회 닉네임`, `/경제기록 번호 거래번호`: 최근 거래 또는 특정 거래를 조회합니다.
- `/경제기록 정리 번호 완료 확인` 또는 `취소 확인`: 실제 결과를 확인한 뒤 기록을 정리합니다. **돈·아이템을 자동 환불하거나 재지급하지 않습니다.** 완료 처리한 땅 예약·직업 선택은 확정하고, 직업 적립금 수령은 적립 기록에서 해당 금액을 차감합니다. 실제 Vault 잔액·아이템을 자동 변경하지 않습니다. 다른 작업을 자동 재실행하지 않습니다.
- `/생활기록 조회 반경 분 [닉네임]`: 최근 블록·상자 변경 기록. 최대 반경 64, 1440분, 최근 500건입니다. 모든 엔티티·WorldEdit 변경까지 기록하는 CoreProtect 대체품은 아닙니다.
- `/생활기록 미리보기 반경 분 [닉네임]`: 60초 유효한 복구 번호를 발급합니다. `/생활기록 복구 번호`로 일반 블록만 역순 복구합니다. 이후 상태가 바뀐 블록·미로딩 청크·상자·표지판 등 타일은 제외합니다. 블록 복구가 이미 주운 드롭이나 다른 곳으로 옮긴 물건을 회수하지는 않습니다. 운영자 판단 후 사용하세요.
- 상자 기록은 같은 틱에 참여한 이용자 집합과 전후 아이템입니다. 개별 아이템을 누가 가져갔는지 확정하는 기록은 아닙니다. 내용 자동 복구는 제공하지 않습니다.
- `/서버백업`: **KoreanEconomy DB·설정만** 일관된 SQLite 스냅샷으로 보관합니다. 자동 30분 간격, 최근 14개. 월드·Essentials 잔액·집·QuickShop 데이터는 포함하지 않습니다. 위치는 `plugins/KoreanEconomy/백업/`입니다.

기존 1.2 전체 예약 백업은 기존 관리자를 통해 계속 동작합니다. 아래 Java 도구의 수동 전체 백업·복원은 서버와 관리자를 끈 뒤 압축을 푼 배포 폴더에서 아래처럼 실행합니다. 전체 백업은 설치 때도 자동으로 만들어집니다. 설치·복원은 서버 종료 확인을 요구하고 월드 잠금을 점검하지만, 실행 도중 다른 창에서 서버를 다시 시작하는 상황까지 차단하지는 않습니다. `session.lock`은 재생성되는 파일이므로 백업에서 제외합니다.

```text
java -jar 설치도구.jar 백업 "서버폴더" --서버종료확인
java -jar 설치도구.jar 검증 "전체서버-날짜.zip"
java -jar 설치도구.jar 복원 "서버폴더" "전체서버-날짜.zip" --서버종료확인
```

전체 백업은 `서버폴더/tycoon-server-backups/`에 저장합니다. SHA-256을 검증하고 복원 직전 현재 상태도 다시 백업합니다. 복원은 월드와 잔액·사용자 데이터를 같은 시점으로 되돌리는 전체 복원입니다. 백업 폴더는 자동 삭제하지 않습니다. 디스크 사용량을 확인하고 별도 디스크에도 복사하세요. 심볼릭 링크가 있는 서버는 자동 작업을 거부하므로 별도 수동 백업이 필요합니다.

외부 Vault 경제 저장소와 플레이어 NBT를 하나의 원자적 DB 거래로 보장할 수 없습니다. 불확실한 결과는 확인 대기로 남기고 해당 이용자의 추가 자체 거래를 막습니다. 이전 `보상기록/*.properties`는 삭제하지 않고 한 번 가져옵니다. 처리 중이던 보상은 확인 대기로 유지됩니다. 복구를 위해 DB나 보상 기록만 임의 삭제하지 마세요.

## 선택 리소스팩

동봉한 `생활타이쿤-리소스팩-26.3.zip`을 각 이용자의 `.minecraft/resourcepacks`에 넣고 게임에서 선택하면 됩니다. Minecraft 26.3 리소스 형식 97.1용 자체 픽셀 아이콘 10종입니다. 서버가 팩을 자동 배포하거나 클라이언트 폴더를 수정하지 않습니다.

**모든 이용자가 적용한 뒤**, 제작을 시작하기 전에 `plugins/KoreanEconomy/config.yml`의 `리소스팩-사용: true`로 설정하고 재시작하면 신규 요리에 전용 모델이 붙습니다. 기본값 false에서는 일반 음식 아이콘을 사용하며 모든 기능을 이용할 수 있습니다. 매입은 전용 모델을 켜기 전과 후의 정식 요리를 모두 받습니다. 실제 26.3 클라이언트 화면은 이 환경에서 확인하지 못했습니다.

## 서버 메모리

총 RAM 16GB의 실제 Windows 서버에서는 기존 관리자 설정 `-Xms512M -Xmx2048M`을 유지했습니다. 동시 활동 부하는 별도 검증이 필요하므로 TPS·힙·운영체제 여유를 보며 조절하세요. 2.0.1 실행 검증은 기존 JDK 27 환경이며 운영체제와 게임 클라이언트 메모리도 남겨야 합니다. 최신 설치·검증 안내는 `releases/tycoon-2.0.1/`을 참고하세요.
